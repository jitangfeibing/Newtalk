# Newtalk Web 前端规划

本文记录 Newtalk Web 的页面信息架构、分阶段实施顺序和验收边界。前端继续使用原生 HTML、CSS 和 JavaScript；在现有功能稳定前，不为了页面改版提前引入 React 或新的构建工具。

## 产品定位

Web 是 Newtalk 的主要客户端，不再以“协议测试控制台”为主要视觉形态。用户首先看到家庭陪伴助手，需要时再进入成员、声纹、画像和长期记忆管理。

## 页面结构

左侧导航固定提供四个入口，每次只显示一个主视图：

```text
Newtalk
├── 首页
│   ├── 时间问候
│   ├── 产品能力概览
│   └── 开始对话
├── 对话
│   ├── Dialogue 历史
│   ├── 文字输入与说话人
│   ├── 麦克风 / ASR / VAD
│   ├── 流式回复 / TTS / 停止播放
│   └── 折叠的协议调试信息
├── 家庭成员
│   ├── 家庭设备与恢复码
│   ├── 成员资料
│   └── 声纹录入、重录和删除
└── 记忆中心
    ├── 当前成员
    ├── Profile
    └── 长期 Memory
```

侧栏连接状态属于全局状态，在四个视图之间切换时保持可见。WebSocket、AudioWorklet 和当前 Dialogue 不因视图切换而重建。

## 实施阶段

### F1：首页框架与对话

状态：已完成第一轮。

- 建立侧栏和单视图切换。
- 首页提供问候、能力概览和对话入口。
- 对话保留现有 WebSocket、文本、麦克风、TTS、打断、成员选择和 Dialogue 恢复。
- 对话支持开始新对话，清除当前 Session 的全部短期 Dialogue，但保留长期数据。
- 协议事件降级为折叠的开发信息，不再占据主界面。
- 桌面、窄屏和移动端保持可用。

### F2：家庭成员与声纹

状态：已完成第一轮。

- 把现有成员表单整理为“成员列表 + 成员详情”的管理界面。
- 将创建家庭、恢复家庭和恢复码操作放入清晰的首次使用流程。
- 声纹录入显示三段录音的进度、质量和失败原因。
- 保持当前 Device、Identity 和 VoicePrint API 不变。

### F3：Profile 与 Memory Center

状态：已完成第一轮。

- 将 Profile 与历史 Memory 分成清晰的常驻信息和按需记忆区域。
- 提供搜索、筛选、编辑、删除、锁定和空状态。
- 明确区分“服务未配置”“服务异常”“确实没有记忆”。
- 保持当前 MemOS Scope 和成员隔离规则不变。

F2/F3 第一轮继续沿用现有 HTTP API，没有调整 Device、Identity、VoicePrint 或 MemOS 协议。当前完成的是可直接对接真实服务的桌面管理界面；移动端细节和统一交互验收留到 F4。

### F4：体验统一与验收

状态：第一轮已完成并通过浏览器验收。

- 统一加载、成功、错误、离线和降级状态。
- 完成键盘操作、焦点、可读性和移动端检查。
- 增加前端关键 DOM 与主要操作链路测试。
- 浏览器人工验收文字、语音、打断、声纹、刷新恢复和 Memory。

本轮以桌面端为验收目标；移动端精调暂缓，后续根据产品交付形态单独规划。

## 技术边界

- 前端只通过 Newtalk HTTP/WebSocket API 访问业务能力，不直接请求 VoicePrint 或 MemOS。
- 不修改后端协议来迁就视觉改版；确有交互缺口时单独定义接口变更。
- 保留关键 DOM `id`，让现有 `app.js`、`identity.js` 和 `memory-center.js` 可以逐步迁移。
- 每个阶段完成后更新 `docs/PROGRESS.md`，通过自动测试和浏览器人工验收后再提交。

## F1 完成标准

- 点击侧栏时只出现目标视图，不再把所有功能堆在一张长页面上。
- 首页和对话在桌面、约 650px 窄屏和手机宽度下不发生内容挤压。
- 切换视图不会断开 WebSocket、丢失 Dialogue 或停止正在进行的 Turn。
- 原有 Ping/Pong、文字聊天、麦克风和音频播放逻辑保持正常。
