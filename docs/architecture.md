# Newtalk 架构与边界

本文描述当前实现及其设计约束。接口字段见 [protocol.md](protocol.md)，未完成事项和验收标准见 [roadmap.md](roadmap.md)；不在此保留阶段进度和历史测试计数。

## 模块与数据归属

| 模块 | 职责与边界 |
|---|---|
| `app` | 组合配置、Provider、Store 和后台服务，管理启动与关闭。 |
| `transport` | HTTP 鉴权后的 WebSocket 协议分发；每连接一个 Runtime，编排 Turn、播放、音频与任务。 |
| `audio` / `asr` | AudioInputSession 用独立 VAD 状态切分 utterance；ASR Provider 只处理语音协议和 partial/final。 |
| `chat` / `tts` | ChatService 编排 LLM、有界工具调用和分句 TTS；工具选择与执行委托 tools 层，不负责各工具业务、声纹或设备鉴权。 |
| `tools` | 统一工具接口、按会话选择的注册表和内置处理器；连接已有业务服务，不管理 Provider 生命周期，不直接操作浏览器。 |
| `identity` / `voiceprint` | Identity 管设备凭据、成员和删除；独立 VoicePrint 服务生成/匹配模板，主服务验证成员归属。 |
| `profile` / `memory` | 成员画像缓存、MemOS 协议、Memory Center 和后台写入；检索权限来自 Turn 中固定的身份。 |
| `reminders` | 设备共享一次性提醒的持久化、调度、播放回执与固定正文 TTS；不依赖长期记忆或聊天生成任务。 |
| `music` / `media` | music 负责音源搜索、解析和设备范围的临时音频转发；连接内 MediaSession 拥有已接受操作、解析任务和网页状态，不进入聊天 PCM。 |
| `web` | 五个业务视图与独立上下文看板；HTTP 管理/诊断数据，WebSocket 传实时事件和 PCM，AudioWorklet 采集/播放。 |

| 状态 | 所有者与生命周期 |
|---|---|
| 当前生成 Turn、播放 stream、发送顺序 | 连接内 Runtime；生成与播放分别记录。 |
| 媒体操作与资源解析、网页播放事实 | 每连接一个 MediaSession；接受后独立于聊天轮，换歌／停止使旧解析失效，断开时回收。 |
| 采集与 utterance、ASR/声纹汇合 | 单次采集及 utterance；用 `utterance_id` 关联异步结果。 |
| 短期 Dialogue | 每设备一个持久化 Session；连接内窗口由进程内协调器同步。 |
| Profile Snapshot | 每连接、每成员缓存；后台预取，Turn 只读创建时快照。 |
| 记忆写入与成员删除 | PostgreSQL 持久化任务，后台 Worker 用租约恢复处理。 |

主库的 ORM 元数据包含 `devices`、`identities`、`dialogue_sessions`、`dialogue_exchanges`、`memory_jobs`、`identity_deletion_jobs`、`recovery_rate_limits`、`reminders` 八张表；独立声纹服务另维护模板表。Alembic 是建表和升级 schema 的入口，应用启动不自动建表。生产 Store 使用 PostgreSQL，内存 Store 主要用于测试。

## 一次语音交互与 Task 归属

```text
接收循环 Task：Cookie 鉴权 -> 打开设备 Session -> hello(历史快照)
  浏览器 AudioWorklet -> 16kHz / 单声道 / PCM16 / 20ms 帧
  -> AudioInputSession.push -> VAD
     speech_start -> 对话模式停止聊天播音/取消旧生成；纯播放模式仅记录语音边界（均不创建 Turn）
     speech_end   -> 通知边界、结束 ASR 输入、启动声纹识别 Task

识别 Task：ASR partial/final -> Runtime 回调
  非空 Final -> 有限等待同 utterance 声纹 -> 校验 Active 成员或降级 Guest
  -> 创建不可变 Turn（身份 + Dialogue + 已就绪 Profile）
  -> 先将最终用户输入加入设备短期窗口；启动独立输入落库 Task
  -> 启动 Turn Task

Turn Task：ChatService
  LLM producer -> text_delta + 分句队列 -> TTS producer -> PCM
  两个 producer 完成 -> 校验仍可提交
  -> 在原用户输入位置补全完整助手回答 -> 数据库补全 -> Member 记忆任务入队
  -> turn_completed

发送 Task：所有实时输出 -> 单一队列 -> WebSocket
  发送前按 turn_id 丢弃旧 Turn 输出
浏览器：播放 PCM -> playback_drained -> 清除匹配的播放状态
```

文本输入跳过 VAD/ASR/声纹，验证所选成员后进入同一 Turn 链路。Profile 预取和记忆/删除 Worker 不运行在 Turn 的生成链路中。

`_turn_transition_lock` 串行化 Turn 替换和取消，包括等待旧任务退出、建立新快照与绑定新任务；它不是整个 Runtime 的全局锁。Turn 流、发送、播放回执和识别回调仍可能交错。取消先使旧 Turn 失效，再清理任务；浏览器必须同时清空尚未播放的 PCM。

接收循环不等待整段 LLM/TTS 生成，但**不保证完全不阻塞**：停止采集会等待识别收尾，打断会等待旧任务退出，鉴权/持久化和输出发送也存在等待。ASR 队列已采用有界非阻塞写入，满队列按单个 utterance 失败处理，VAD 继续运行并保留结束边界。

## 设计决策

### 统一模型工具层

`tools/models.py` 定义 `Tool` Protocol、冻结的 `ToolContext` 和 `ToolResult = str | DeviceControl | MediaControl`。字符串回传模型形成正常回复；冻结的客户端动作直接穿过 TTS 链路交给 Runtime，不伪造控制成功的助手回复。`Turn` 中已校验的设备和成员范围进入每轮独立 context，工具不接受模型指定其他设备/成员范围。

`tools/registry.py` 提供 `ToolRegistry` 和每轮冻结的 `ToolSelection`：选择时由各处理器决定是否提供定义，定义复制后交给模型；执行只按本轮实际提供的处理器分发，未提供的名称返回 unsupported_tool。重复注册名和定义名不匹配明确拒绝。注册表没有共享“当前身份/已调用工具”状态；组合期 with_tool 返回新注册表，已经开始的轮次保留自己的选择快照。

`tools/builtin.py` 组合内置处理器，`tools/memory.py`、`tools/device_control.py`、`tools/reminder.py` 分别维护记忆、页面控制和提醒工具定义、参数入口、执行及相关诊断。提醒 CRUD/调度仍在 ReminderService，记忆请求仍由 MemoryProvider 执行，页面资源仍由 Runtime/网页控制；注册表不拥有后台任务。记忆查询、候选搜索等临时工作随 Turn 取消；音乐播放意图接受后由连接内媒体会话拥有，具体边界见下文。记忆工具沿用既有服务故障降级结果，提醒持久化异常继续使当前轮次失败，不能假称创建成功。

ToolSelection.following 只为声明 followup_tools、且结构化结果 status=ok 的工具保留指定后续处理器；后续必须来自本轮实际提供的工具。ChatService 全轮最多两次调用，第二次后清空工具；其他工具仍在第一次后清空，不允许搜索失败后补播、任意跨工具动作或第三次调用。

ChatService 只编排模型消息、工具轮数、注册表调用和 TTS，保留记忆检索使用统计及 preload 上下文准备。preload 复用 MemorySearchTool.search，按原有超时预算执行，不伪造模型工具调用，也不占模型工具次数。默认工具组合及顺序不变；既有 device_control_enabled 关键字作为兼容入口映射到 context.client_tools_enabled，浏览器工具不受记忆检索模式限制。

新增工具可实现 Tool 并通过构造参数 tool_registry 注入，或在应用组合期使用 with_tool 注册，无须给 ChatService 增加工具名分支。app 为每个应用注册对应 ReminderService、MusicService 和 PodcastService 的处理器。旧 chat/device_control.py 和 reminders/tools.py 仅保留兼容导出，避免原调用方依赖同时变动。当前没有动态插件加载、自动发现或无限工具循环。

### 音乐演示与媒体播放

`tools/music.py` 管理 `music_control` 的定义、参数和工具结果；`music/service.py` 负责搜索候选、序号选择和临时资源；`music/provider.py` 适配 Yaohu QQ 音乐接口；`media/models.py` 定义与内容源无关的意图、动作和事实，`media/session.py` 管理连接内任务。Provider 由 app 组合、关闭，密钥仅从 `NEWTALK_MUSIC_API_KEY` 读取，未配置时不向模型提供音乐工具。Member / Guest 均可点播当前设备的音乐，不依赖长期记忆或新增数据库表。

“播放音乐”默认搜索“轻音乐”，歌手或歌名作为关键词。一次 play 在业务服务内完成搜索和详情解析，最多尝试前三个候选；指定序号只解析该项。详情必须与列表的 mid 匹配且具有实际 musicurl，空地址或会员专用字段不算可播放，不使用会员 Cookie。搜索顺序与可用歌曲取决于第三方，当前不能保证任意歌手或付费歌曲可播，也不构成商用可用性承诺。

音乐能力说明与操作工具分开：配置启用时，每轮都提供带 enabled 的网页媒体资料；只有当前输入具有播放、搜索、换歌或音乐控制表达时才提供操作工具。系统提示解释“本轮无需操作”不代表能力不可用。执行入口再次检查当前请求，避免仅因历史点播或歌曲评价产生动作。历史点播、单纯评价歌曲或转入普通聊天不授权重新播放；误调用时不产生 MediaControl，而是回传 status=ok/action=none/reason=not_requested 和功能可用信息，让既有工具后续模型轮正常回答。仅说“继续”保留由模型结合上下文判断的入口，“继续聊聊刚才的话题”走普通聊天。工具执行时对完整“暂停音乐／继续播放音乐／停止音乐”等明确口令校验动作，防止模型把控制误写成重新点播；不匹配泛指聊天的“停止”。当前使用保守的操作表达匹配，不能覆盖全部自然说法；不识别的点播可改用“播放＋歌手／歌名”或按钮。符合条件后的动作和参数仍由模型判断，按钮直接执行对应动作。

播放资源使用随机编号，仅绑定已鉴权设备；查询候选缓存 10 分钟、至多 128 个设备，音频地址缓存 30 分钟、至多 256 条。网页只收到标题、歌手、来源和同源音频路径，第三方密钥、签名地址与会员字段不交给模型或网页。转发只允许指定 QQ 音频域名与 HTTPS，逐跳校验重定向，支持单段 Range，断开时关闭上游流。HTTPX 请求日志对接口密钥和音频票据查询串脱敏；不记录第三方完整响应。

语音工具与按钮统一提交 MediaIntent。ToolContext 注入仅对当前有效 Turn 可提交的 MediaCommands；未接受前的迟到意图被拒绝。接受后立即返回带 operation_id 的 accepted 结果，经过既有工具结果模型轮生成简短确认；实际工具调用和 accepted 结果只用于该轮模型请求，完整工具消息尚未持久化，Dialogue 仍保存用户输入及已完成助手回复。聊天取消不撤回已接受操作，候选 search 仍属于当前聊天轮。

MediaSession 按 source 调用资源解析器，独立于 LLM/TTS；目前注册 music 与连接内 podcast 内容源。换歌／停止递增版本并取消旧解析，即使旧源忽略取消后迟到返回，也不能投递旧资源或旧错误。暂停不取消解析，只改变期望状态；暂停期间资源就绪时发送 autoplay=false，让网页准备曲目但不出声。解析期间继续复用原操作，资源已就绪时继续直接控制网页。每连接最多 8 个在途任务，一项有效解析；play 总预算 25 秒，关闭连接取消并等待任务退出，依赖源适配器遵守 asyncio 取消。不在接收循环内等待音乐供应商；这不改变其他既有等待边界。

资源就绪后以不带旧 turn_id 的连接事件发送 MediaControl，不能因旧聊天失效而过滤已接受操作。media_status 展示待查找目标、操作状态和错误；media_result 按 request_id／动作关联，最多保留 16 个，waiting 续期，其余回执结束等待，90 秒后失效并在后续控制时清理。media_state 在一次回执结束后继续报告自动暂停、自然结束和播放器错误，仅最近控制的关联编号可更新状态。源错误区分无资源、上游错误、超时和无效响应，日志记录操作编号、候选序号、阶段及耗时，不把空地址推断成会员或版权限制。媒体事件只更新网页和事实，不额外启动 LLM 或自动语音播报。

冻结的 MediaObservation 同时记录待处理目标与已准备曲目，以及最近网页状态；下一轮以明确标记的 user 资料消息注入，不写入 Dialogue 或长期记忆。模型资料由代码根据 client_status 生成 playback_summary，区分已暂停、等待、播放中、结束及未知；解析中的新目标另作说明。模型资料不暴露内部 desired_playing 调度标记，最近 action 和 operation_state 也不代表正在出声；网页事件和调度仍保留原字段。已暂停的曲目不因普通聊天自行恢复，回复不得暗示其仍在播放。accepted／resolving、资源就绪和网页实际 playing 分开；没有匹配反馈时不能宣称已出声。网页报告仍有传输延迟，不代表服务端直接听到了声音。断开、刷新建立新连接后不继承该快照。

`web/media-player.js` 使用独立 HTMLAudioElement，不复用聊天 PCM 或提醒正文元素。页面按真实 playing 事件报告开始，浏览器拒绝播放时显示手动继续入口。已开始的音乐/节目进入纯播放语音模式；普通声音不暂停，明确暂停/停止后恢复对话。文字输入、聊天生成/播音或提醒仍可暂停媒体，结束后不自动恢复；明确的新点播／继续若尚未开始，会保留待播请求，等前台忙闲条件全部释放后尝试播放。新版本的查找会撤销旧的待播请求，迟到控制和源错误按版本丢弃。提醒保持完整播报与下一轮生成门控。暂停、继续、停止及音量均可手动控制；刷新或断线停止并清空本页媒体状态，不自动续播。当前没有播放队列、音乐下一首、歌词、收藏或进度持久化；喜马拉雅听书边界见下文。

### 纯播放时的语音入口

网页确认 playing 且当前仍期望播放时，语音进入 media_only；暂停/停止请求已接受、网页报告暂停/结束/失败后回到 conversation。该状态由 MediaObservation 计算，不另建一个可能与回执漂移的播放开关。进入纯播放后，VAD 与 ASR 继续运行，VAD 开口事件不暂停音乐/节目、不取消旧聊天任务。普通识别结果、切歌/换集请求及空结果不创建聊天轮、不写入 Dialogue 或长期记忆，也不触发额外声纹识别；需要先暂停/停止再说后续要求。

纯播放时仅对 ASR Final 的完整退出口令作固定匹配，例如“暂停”“暂停播放”“停一下”“停止播放”“停止节目”。不依据 partial 或词的子串停播，“不要暂停”“暂停是什么意思”“暂停吗”不执行。确认后直接向连接的 MediaSession 提交 pause/stop，取消残余聊天生成，不调用大模型或等待声纹；暂停保留当前曲目，停止释放网页音频。网页执行后即可按原对话链路聊天、换歌、换集；继续/新点播实际 playing 后再次进入纯播放。文字输入与按钮是明确交互入口，不受此语音过滤限制，提醒仍沿用既有优先级。

每个语音段固定开口时模式并关联当时播放请求/操作编号；播放结束后的迟到普通转写不能变成新聊天，旧播放的迟到停止指令也不能作用于新播放。忽略的 partial 不转发，final 使用空 text 和 ignored_media 标记，前端不追加聊天消息并清理临时时序/忙闲标记；服务端普通日志只记录长度与处理原因。ASR 仍在后台处理采集内容，并非本地唤醒词识别；外放回声下识别完整口令的实际效果需在目标设备验收，VAD 参数与浏览器 AEC 配置没有改变。

### 喜马拉雅听书与无屏选择

`podcasts/provider.py` 适配 Yaohu 喜马拉雅接口，`podcasts/service.py` 分开应用级 Provider/临时资源与每连接 PodcastSession；`tools/podcasts.py` 提供 podcast_search 和 podcast_control。密钥优先 NEWTALK_PODCAST_API_KEY，未配置时复用 NEWTALK_MUSIC_API_KEY，不使用会员 Cookie。无需新增数据库表，Member/Guest 都可控制当前连接。

首版交互为明确点播匹配后直接播、泛听帮助选择、存在明显类型/版本歧义时简短澄清；最多介绍两个有区别的候选。该语义选择由模型结合真实元数据完成，不能当作确定性识别保证。工具支持 search、候选序号/名称选择、换一个候选专辑、下一集/下一期以及暂停/继续/停止。纯查找请求不自动播放；控制端校验真实 selection_id 和当前候选序号，不从历史助手编造专辑。普通评论不应触发动作，歌曲工具与听书工具按内容源区分。

搜索最多取 10 条，模型候选最多 5 条；program 类型过滤标题中明确的小说/课程等不匹配内容，auto 保留类型歧义供模型澄清。每连接保留至多 8 份、每份 10 分钟的候选快照，接受后的操作固定关联当时快照；另一连接或后续搜索不会改写已接受序号。解析前用专辑标题、主播及源序号核对专辑，变化时报 selection_changed；接口未提供稳定专辑/单集 ID，不能宣称具备跨次稳定映射。

series 连续内容按 orderNo 核对第 1 集，排除明显预告/广告；第一页未找到时只再检查末页，不扫描整本。首集无法确认、收费或缺少地址时明确失败，不跳播后面的集数。小说下一集按集数递增，在当前及相邻页寻找，不能跨过不可播的一集。program 独立节目从列表首个非推广、可播条目试听，下一期沿网站返回列表向后，跨页仅取下一页；当前网站样本为从新到旧，因此通常听到更早一期，不将缺号强行补成连续编号。页面未提供可靠发布时间，模型不编造具体发布日期或最新保证。

已选择专辑与已准备单集分开记录，某专辑加载失败后仍可“换一个”。搜索受当前聊天取消，迟到结果不能提交新候选；已接受的播放/换专辑/下一集归 MediaSession，插话继续沿用独立任务、版本失效和网页忙闲规则。连接关闭只清理自己的候选/选集，不关闭共享 Provider。不会自动连播下一集，不做跨次断点、收藏或会员登录。

网页复用现有播放器和状态卡片，额外显示专辑、主播与来源，控制当前媒体。音乐/听书音频经 media/api.py 共用鉴权、Range 转发及断开关闭；内容源各自校验域名与重定向，听书只允许 HTTPS 的 xmcdn.com 子域，源地址、票据和密钥不交给模型或前端。资源按设备隔离、最多 256 条、30 分钟过期，重连后重新选择，不保证旧地址长期有效。上游 503、超时、无资源均如实记录，不自动换成另一专辑冒充成功。

### 当前页面控制

完整文字／ASR Final 中的固定控制口令在聊天 Turn 之前分流，不访问成员资料，也不写入 Dialogue；其他表达继续使用现有 LLM，由 `device_control` 工具给出固定动作。该工具在连接的 `stream_turn` 中启用，独立于 Member／Guest、记忆服务开关和 `tool`／`preload` 模式；独立调用 ChatService 时默认为关闭，以免没有浏览器执行方时生成悬空控制。默认每轮最多一次模型工具调用；只有成功的听书搜索允许一次指定播放后续，前置记忆查询不占用模型工具次数。

模型工具输出为冻结的 `DeviceControl` 事件，直接穿过生成链路，不进入文本分句或 TTS，不伪造已完成的助手回答；原有已接受输入独立保存。Runtime 发送控制请求，浏览器执行，独立有界回执 Task 记录结果；不在 ASR 回调或当前 Turn 内等待关闭自身。停止回复同时取消生成和清空播放；关麦释放采集资源并保持文字连接；主动断开清理本页资源及连接，不清空历史、成员或记忆。按钮与控制事件复用前端动作，当前摄像头动作仅报告未开启。

明确口令和按钮的控制请求由连接持有的独立 Task 执行，接收循环不内联等待该次 LLM/TTS 取消；这些在途任务和待回执请求合计最多 16 个。回执等待 5 秒无结果标为未知；连接关闭时取消并回收控制及回执任务。结果只表示客户端所报告状态，断开接受与实际关闭分开。浏览器按请求去重、隔离旧连接，单项资源关闭等待最多 2 秒；麦克风先摘除当前采集资源，再等待旧 AudioContext 关闭，防止迟到关闭覆盖新采集。具体事件见 [设备控制协议](protocol.md#当前页面的设备控制)。

模型设备控制执行前也检查本轮是否存在控制表达，避免历史停止命令把新一轮普通聊天停掉；无需动作时回传正常的 no-op 结果，由既有后续模型轮回应。控制不读取其他家庭数据，也不等于严格的个人鉴权；当前设备的 Guest 同样可停止或关闭本连接。固定口令采用整句匹配，任意自然表达仍依赖 ASR／模型理解，不保证绝不误判。原有接收循环的取消和发送等待边界仍存在，本功能没有消除这些等待。

### 设备共享的一次性提醒

`reminders` 一行代表一条提醒，包含 `reminder_id`、设备外键 `device_id`、至多 160 字的 `content`、带时区的 `due_at` / `created_at`、幂等键 `request_key` 和业务 `status`。`(device_id, request_key)` 唯一；`(status, due_at)` 支持调度扫描，`(device_id, due_at)` 支持设备列表。最近一次投递使用 `delivery_id`、`delivery_status`、`connection_id`、`delivery_deadline`，没有播报历史表，也不存音频。新增迁移只建该表及两个索引，不改变既有表的 CHECK 约束。

提醒属于 Cookie 绑定的设备家庭空间，Member / Guest 均可管理和听到正文，不提供家庭内部私人提醒。`reminder_manage` 与页面控制一起在浏览器聊天中启用，独立于记忆开关和检索模式；单轮仍最多一次模型工具调用。只根据当前明确请求执行；相对秒数由服务器时钟计算，绝对时间要求时区，工具说明提供当前北京时间。网页输入按北京时间解释。仅接收未来一年内的一次性时间；含糊时间要求模型澄清，真实解析效果仍需对话验收。修改/取消需真实编号，首次查询后的操作可由下一轮或工具页完成，不增加无限工具循环。

`ReminderService` 独立轮询数据库，每轮最多认领 50 条，约每秒检查一次；PostgreSQL 使用行锁和 `SKIP LOCKED`，更新/取消与认领通过状态条件串行生效。到点有在线连接时，只向该设备最近建立的一个连接发送 `reminder_due`；不按麦克风是否开启判断在线。离线记录 `missed`，重连/重启不自动集中补播。刷新或“新对话”不删除提醒，删除成员也不删除设备共享提醒。没有自动保留期限，列表最多返回最近到期的 200 条，工具查询最多 30 条；历史分页和定期清理未实现。

业务状态为 `scheduled / triggered / missed / cancelled`；播放另记 `pending / playing / completed / interrupted / failed / expired / unknown`。网页等待当前聊天生成及实际 PCM 播放结束后，使用独立音频元素播放提示音和固定正文“提醒你：正文”。短 WAV 由与聊天同配置、独立生命周期的 TTS 实例生成，不再调用 LLM，不混入聊天的无标签 PCM 二进制流；合成最多等待 15 秒、并发 2、正文音频最多 60 秒，内存保留最近 16 份，不落磁盘。

前端通过独立队列协调聊天/用户说话与提醒：到点时已开始的回复可以结束，下一轮回复之前优先完整播报提醒；取消原先等待 30 秒后放弃的规则。提醒开始后，普通说话、VAD、聊天停止指令与后续问题都不抢占提醒。用户新输入仍按原链路接受和独立落库，下一轮生成 Task 发出 `turn_waiting` 后等待连接内提醒门控，不在接收循环等待；同一连接多个在途提醒全部结束后才进入 LLM/TTS。连续输入仍沿用原有新 Turn 替换旧 Turn 的规则，旧输入保留，但不承诺为每条被替换输入分别补回复。

网页在排队和开始播放之前每 15 秒发送 waiting 回执续期，状态仍保持 pending，避免正常长聊天被当作投递丢失。浏览器阻止播放时如实标记失败，工具页保留主动启用提示音和重播。明确点击“停止提醒播放”、取消对应提醒或断开连接仍能停止播报；普通“停止播放/别说了”只作用于聊天。取消一条提醒会停止其排队/当前播放。重播产生新 `delivery_id`，迟到回执不能改变新投递。

播放回执由连接持有的单任务按顺序落库，队列最多 32 条、单次等待 5 秒；接收循环不内联等待该次数据库写入。回执同时核对设备、连接、提醒和投递编号；开始播放仅从 pending 转 playing，播完仅从 playing 转 completed。waiting 续期或真实开始播放后，delivery_deadline 延长到当时起 90 秒；超过截止时间没有有效续期/终态、断线或服务重启时，待确认播放标为 unknown，不自动重试。终态/超时通知释放对应连接的生成门控，页面也丢弃匹配投递，避免提醒失败后一直卡住聊天；终态或回执丢失不能保证用户实际听到。已保存提醒不随聊天取消而撤销；存储提交时连接中断可能需要查询实际结果。服务端调度与连接注册表目前仅支持单进程；多 worker、精确闹钟、休眠唤醒、离线通知、循环任务和稍后提醒不在当前实现内。提醒开始会暂停音乐，恢复需用户明确操作。

### 设备共享对话，成员私有记忆

同一 `device_id` 的 Member 和 Guest 共用最近 Dialogue；声纹只确定当前说话人和 Profile/Memory 权限，避免未命中时丢失前文。数据库 `family/guest` lane 暂作兼容元数据和恢复查询分组，不再代表两个聊天通道。

Profile 常驻注入就绪快照；长期记忆通过 `NEWTALK_MEMORY_RETRIEVAL_MODE` 在 `tool`（默认、模型按需检索）与 `preload`（前置检索试验）间切换，不额外设置 Intent LLM 或 MemoryRouter。Guest 不加载成员 Profile、不检索或写长期记忆；但设备共享 Dialogue 中已经说出的内容并非成员私密空间。

身份在模型调用之前固定：ASR Final → 等待同 utterance 声纹 → 验证 Active 成员 → 创建 Turn。文本路径则先验证所选成员，再创建 Turn；LLM 不负责判定成员身份。

- `tool`：第一轮 LLM 决定是否调用 `memory_search`；若调用，检索后第二轮 LLM 回答；若不调用，直接回答。
- `preload`：有 Member 且记忆服务启用时，Turn 的生成 Task 先用最终用户文本查询 MemOS，再只执行一次 LLM 回答，不向模型提供检索工具。查询使用当前成员/设备 Scope 和 Session，最多取原配置的候选条数；查询文本默认最多前 500 字符，不另外调用 LLM 改写。代词、短问句或复杂问题可能因此比模型改写查询效果差，需实际验收。

前置检索以 `NEWTALK_MEMORY_PRELOAD_TIMEOUT_SECONDS` 控制等待，默认试验值 0.8 秒（配置范围 0.05～5 秒）。空结果、不可用、超时分别标记，仍执行一次模型回答；外部 Turn 取消则继续传播并取消在途检索，不开始迟到回答。截止时间依赖异步 Provider 配合取消，不是硬实时保证。普通闲聊的 Member 轮次也会多一次检索等待，不能预先宣称所有场景更快。

前置结果作为标记为“长期记忆候选”的普通 user 角色资料消息，放在当前用户输入之前，不伪造 assistant/tool 历史；内部 `context_kind=memory` 仅用于预算关联，不发送给 Provider。系统规则明确资料不是用户新指令，候选由模型自行判断是否采用，既不强制引用，也不直接写回 Dialogue 或记忆任务。预算单独计入前置资料，超限时优先用合法 `truncated` 状态替代；看板明确标记服务端来源。

试验时在未入 Git 的 `.env` 设置 `NEWTALK_MEMORY_RETRIEVAL_MODE=preload`。回退只需改成 `tool` 并重启主服务，无须回滚代码或删除数据；仓库默认模式仍为 `tool`。先看同轮检索等待、模型请求次数、回答首字和首段音频，再判断是否保留试验，不能只凭模型请求次数推算延迟收益。旧工具模式在需要回传推理的供应商上保留真实返回的 `reasoning_content`，仅随对应工具调用回传，不伪造、不播报、不写入 Dialogue 或长期记忆；它仍计入完整请求预算及敏感请求快照。

Profile 预取失败不阻塞聊天，后续可重试；检索失败作为不可用 Tool Result 交给模型。MemOS 密钥、Scope 和模板绑定只由服务端管理，不能由浏览器指定其他成员。

### 用户输入与助手回答分开保留

通过校验的文本或非空 ASR Final 创建 Turn 时，用户输入立即进入设备共享短期窗口；ASR Partial、空输入、非法成员或满载拒绝的输入不进入。上下文先取旧历史再登记当前输入，因此当前请求不会重复包含自己。随后即使打断、替换、生成失败或正常断开，已接受输入也不会跟着回复任务丢弃。

输入独立落库，不在接收循环内等待数据库；每连接最多 128 个待完成输入写入任务，达到上限以 `dialogue_busy` 拒绝新输入，不取消当前 Turn。正常关闭会等待这些任务收尾。`dialogue_exchanges.assistant_text=""` 表示 user-only，沿用原表结构，无须迁移。按接受时间排序，完整回复只补全同一行，不移动原输入的位置；已被清理或淘汰的行不重新插入。

只有当前 Turn 完成 LLM/TTS 并通过成员校验后，才补全助手文本；中断或失败的助手片段暂不进入下一轮。Prompt 可以包含连续 user 消息，不伪造空助手回答。长期记忆仍只写完整、确认持久化的 Member 交换，独立保留输入不等于单独写长期记忆。

原文存储、候选缓存、模型请求是三层独立边界：数据库追加不再根据窗口删除旧原文，Member 与 Guest 原文均保存到显式新对话或删除对应成员时；没有自动保留期限，不能对外承诺无限、无成本保存。旧版本已经删除的历史不会自动恢复。候选缓存默认保留最近 256 条用户输入，恢复查询每 lane 最多加载相同条数，Runtime 合并后取最近候选；更早原文虽在数据库，尚无历史分页或自动重载进入本轮的能力。候选数可通过 `NEWTALK_DIALOGUE_MAX_TURNS` 调整（1～2000）；已有显式设置 8 的环境不会被默认值自动覆盖。

进程内按设备串行化输入写入、清空与成员记录清理，用清空版本/已删成员标记阻止旧任务写回；SQL 追加时还锁定并校验 Active 成员。恢复快照过滤已停用成员；同进程新连接继承活跃窗口，避免落库尚未完成时下一轮漏掉输入。

**生成完成仍不等于播放完成**：浏览器在服务端完成后可能还在播放缓冲音频，此时打断只停止播放，不自动撤销已经补全的交换。助手生成、已发送与实际播放片段的区分留待下一步。

新对话清理设备全部短期 Dialogue 和本进程活动缓存，不删除 Profile、长期记忆、成员或声纹。刷新通过 `hello.dialogue` 重建窗口；同进程多页面共享上下文，但不实时广播聊天列表。

### 完整请求预算

`NEWTALK_CONTEXT_INPUT_TOKENS` 默认 32768，范围 256～262144，是应用输入预算，不是供应商模型容量。`NEWTALK_DIALOGUE_MAX_CHARS` 已废弃，配置残留时启动告警，不把旧字符值当成 Token 值。原始候选在 `DialogueSession` 中不再按字符裁剪；正式模型适配器拼好角色提示、Profile、说话人标签、全部候选、当前输入、工具定义或工具结果后，对每一次请求独立执行预算检查。

当前没有匹配实际供应商模型的 Tokenizer，使用 JSON 字段的 UTF-8 字节长度与结构余量做保守 Token 估算，通常会高估，不是精确 Token 数、计费数或供应商硬上限保证。预算只控制输入，输出上限仍沿用 Provider 原有设置；不宣称已实现自动读取模型容量或精确的输出空间预留。后续需要用实际 usage 与模型 Tokenizer 校准。

预算不足时，过大的 `memory_search` 结果先替换为合法 JSON 的 `truncated` 提示，保留工具调用/结果配对，不伪装成未命中；再按最旧用户输入起整组移除历史。系统提示、Profile、当前输入不被静默截断。固定部分仍超预算则本次请求不发送，报告 `context_budget_exceeded`；输入独立保留，下一次较短输入仍可继续。裁剪只修改请求副本，不改原文、Turn 快照或长期记忆写入内容。

这一步不增加 LLM 调用、不自动摘要，也不设置必须存在的任务目标。较长的原始窗口可承接英语学习等连续任务，但超过预算或候选范围仍可能缺少旧目标；不能据此保证无限长任务连续性。带来源的任务状态、摘要生成和长期记忆预取单独验收。

### 上下文调试与回复规则

`NEWTALK_CONTEXT_DEBUG` 默认关闭。开启后 Runtime 记录身份原因、历史候选和近期观察到的缓存排除原因；模型适配器在完整预算取舍后记录准备发送的请求，工具第二轮也单独记录。每条 `llm_request` 附带独立 `budget`，包括估算方式、裁剪前后占用、各部分开销、选入/排除的历史 turn_id、工具结果是否省略。预算拒绝另记 `context_budget_rejected`，不伪装成已发送请求。ChatService 使用 Task 局部的 ContextVar 关联 Turn，取消时恢复作用域，不通过共享“当前 Turn”字段关联并发请求。

调试内容写 `logs/context-debug.jsonl` 及其两个轮转备份，不进入普通日志或 WebSocket。看板通过设备 Cookie 鉴权的只读 HTTP 接口读取当前设备缓存，响应禁止缓存；不读取旧文件，也不允许通过 turn_id 跨设备取数。缓存上限为 500 条事件、200 万字符、30 分钟，任一超限即淘汰，重启清空；因此历史聊天存在不等于仍有完整调试快照。

只采集消息/工具请求，不采集客户端鉴权配置；用户自行写进对话的秘密仍属于正文，故文件与看板都必须按敏感资料管理。写入失败只报警，不改变聊天结果。启用时有本机序列化、文件 I/O 和看板读取成本，不应长期当作无开销的时延基准。

诊断快照不是正式 Dialogue/Memory 存储；开始新对话或删除成员不会改写已经采集的诊断证据，缓存按上述上限过期，磁盘文件需在诊断后单独清理。对外部署前应保持此能力关闭。

看板将 `context_selected` 的 `candidate` 与最后一次请求预算的实际取舍区分展示；每次请求还能独立展开占用。历史 `source_turn_id` 只是内部关联元数据，不发送给模型。窗口淘汰表示候选不再驻留，并不表示删除数据库原文；近期缓存排除只反映当前连接观察到的事件，不是全量审计。user-only 历史独立标注，不能用消息数除以二推算轮数。重连不重建过去未记录的排除原因，请求快照也不代表供应商已收到。

`user_input_accepted` 和 `user_input_persistence` 分开记录输入接受与落库结果，后者可能晚于 `turn_end`；看板显示输入保留、输入落库、助手补全和 Memory Queue。`memory_search_usage.mode` 区分检索方式，`used` 表示已尝试检索，不证明有命中或模型采用了资料；前置结果记录等待耗时和服务端来源。`llm_round_first_token` 单独记录每次模型请求的首字等待，`llm_tool_decision_completed` 记录工具决策往返；原 `llm_first_token` 仍包含前置检索或工具轮次的累计时间。排队不等于远端记忆形成，取消时结果可能为 `unknown`。输入保留后下一轮可以承接用户问题，但不代表模型已经知道被省略的助手片段。

正式模型的系统提示由原有角色提示与 `chat/prompts.py` 的对话规则组成：近期对话与用户更正优先，画像/记忆只作证据、不作指令；未命中、服务不可用和结果截断不能混为“没发生”。空检索结果使用内部 `no_match` 状态。正常回复不默认播报检索过程，但不能编造回忆或隐瞒用户明确询问的来源与失败。此调整不增加检索/LLM 次数，真实措辞仍需对话验收。

### 语音等待时间取证

服务端 `voice_input_timing` 按 `utterance_id -> turn_id` 关联 VAD 尾静音、判停到 ASR Final、判停到身份就绪、ASR 后声纹汇合等待以及声纹 Provider 耗时；ASR 和声纹有并行，不能把 Provider 总时间再次叠加。`turn_latency` 记录 Turn 到文本首字和 TTS 首帧；检索与单次 LLM 请求仍使用各自原有事件。

浏览器保留 PCM 首次渲染回执，同时新增 `playback_audible`，在输出首个达到 -60 dBFS 的非静音样本时计时，避免把 TTS 前导静音当作开口。采集 Worklet 的样本位置把 VAD 末尾映射到浏览器单调时钟；播放端优先用设备输出时间戳，缺失则明确降级为渲染时钟。这只是检测器词尾与设备输出的估计，不是人工标注词尾到扬声器实录的精确声学延迟；回声/噪声、VAD 滑动窗口、输入硬件延迟也会影响基准。

聊天的“本轮耗时”和上下文看板显示不同口径；调试开启时播放回执也进入设备隔离的有界缓存与私有轮转文件，普通日志只记录 ID 和数值。看板可导出当前设备最近 5 轮时延，不导出完整提示词或记忆正文；该导出不是自动划分的实验组，需确认均属本次测试。历史回放不恢复浏览器时延，也不能将缺失回执解释为 0ms。

人工测试：每组先“新对话”，固定身份、5 句话、耳机/音量/网络和检索模式，逐轮等首声、避免打断，再导出。此操作不会冻结 Profile、MemOS 检索返回或后台记忆写入，属于链路诊断，不是受控 A/B。严格对照还需使用同一录音并标注真实词尾，固定上下文与记忆快照、交替重复两种模式；目前未实现自动录音回放基准或声学回环测量。

### LLM 请求细分计时

`llm_request_timing` 以独立 `call_id` 关联 `llm_request`，记录本地准备、SDK 开始、每次 HTTP 尝试、DNS/TCP 与 TLS 阶段、响应头、首个 SDK 流事件、首个思考片段和回答首字。全部毫秒偏移基于同一单调时钟；SDK 重试保留默认预算，连接事件通过 HTTPX/httpcore 的请求级回调采集。ContextVar 和每次尝试的闭包隔离并发请求；取消、异常、消费者提前结束仍关闭 SDK 流并复位作用域。

只记录时长、状态码、安全格式的供应商请求 ID、请求字节数/估算 Token、业务请求 SHA-256 以及供应商可选返回的 Token/cache usage；不记录密钥、原始 Header、异常正文或思考正文。普通日志保留此诊断元数据，私人看板只在原有调试开关开启时采集。注入自定义客户端或传输不提供 trace 时标为未观测；没有建连事件不能直接证明连接复用，响应等待也不能直接称为供应商排队或纯推理耗时。指纹仅证明业务请求相同，不证明云端随机性、缓存、调度或 HTTP 封装相同。

SDK 的 chat/completions 资源在模型构造（启动阶段）准备，避免延迟导入由第一条用户请求承担。此操作不发送预热 API、不改变思考、超时、重试、模型或消息；启动可能增加约一秒本地准备时间，不代表云端已预热，也不保证每次对话首句减少固定时长。

DeepSeek 的思考扩展通过 `NEWTALK_LLM_THINKING=default|enabled|disabled` 显式配置；仓库默认 `default` 不发送扩展、保留供应商行为，其他兼容供应商不应随意启用此字段。语音验收可以显式切换思考模式，修改本地 `.env` 后重启生效；本地配置不提交。消息、模型、记忆和音频策略不随该开关改变；预算/请求快照记录实际线上 `thinking` JSON，SDK 经 `extra_body` 发送，看板明确展示当前请求的开关状态。当前是服务端统一模式，尚未实现按用户或复杂任务自动切换的深度模式。

`scripts/probe_llm_latency.py` 可从私有日志选择一个不含工具、仅可附带 `thinking` 开关的首个文本请求，冻结系统提示、身份资料、记忆候选、历史和原思考模式，按“新客户端/立即再次使用客户端”复测。脚本不启动 Runtime、不检索或写记忆、不写 Dialogue、不生成 TTS；真实调用需显式确认，默认两组共 4 次，会产生 API 费用。它只诊断 LLM，不是完整语音或声学回环测试；结果及完整请求快照仍须按敏感日志管理。

```powershell
.venv/Scripts/python scripts/probe_llm_latency.py --turn-id <已记录的Turn-ID> --cycles 1 --confirm-live
```

### 记忆写入与成员删除协调

```text
成功 Member Turn -> 本地 memory_jobs（turn_id 去重）
  -> Worker 领取 -> Add Message -> 保存 submitted + provider_task_id
  -> 查询同一任务 -> completed / 失败退避重试

删除成员 -> 同一事务标记 deletion_pending、终止未提交记忆任务、登记删除作业
  -> 阻止新记忆提交；已提交远端任务继续查询直到终结
  -> 清理 VoicePrint / MemOS / Dialogue -> 物理删除 Identity
```

提交阶段与删除调度使用同一成员行锁协调，内存实现使用对应成员锁；删除 Worker 清理 MemOS 前检查已提交任务，避免清理后又写回。删除失败持续退避重试，最多间隔 300 秒；记忆提交默认最多 8 次。活动成员的同一远端任务默认最多轮询 600 次，耗尽后进入提交失败处理；删除中的成员不能丢弃已知任务 ID，超限后退避查询，等待远端终结再清理。

本地去重和远端任务追踪不等于严格一次投递：远端接收 Add Message、但响应/任务 ID 尚未落库的窗口仍可能重复。关闭过往使用的 Provider 后，删除会跳过该远端清理，遗留数据需要人工确认。

## 已知边界

- 当前以单进程主服务为部署基线。Dialogue/Profile 协调器只在进程内同步，不能直接据此承诺多 worker 的缓存一致性。
- 停止录音、打断清理、独立输入任务收尾没有统一总预算。接受到内存不等于数据库确认；落库故障会记录失败但不自动重试，确认前进程崩溃仍可能丢失输入。助手内存补全、数据库补全与记忆入队仍非原子，取消时可能不一致；在途 Profile 加载与成员删除的竞态仍需处理。
- 中断助手片段是否保留及如何标识尚未定案；不能把完整生成文本视为用户已听到。完整预算目前为保守估算，长程任务状态、摘要和长期记忆预取尚未实现；ASR Final 到达顺序也不保证等于用户开始讲话的顺序。
- 声纹录入与聊天统一请求单声道、AEC / 降噪 / 自动增益，均经同一 Worklet 转为 16kHz PCM16；浏览器不保证实际采用全部请求参数，聊天诊断可显示实际设置、音量和 VAD 状态。旧模板不会自动转换，需重新录入才能基于新采集设置生成模板。这不等于工程级回声消除或准确率保证；固定 VAD 参数、扬声器回声和复杂噪声仍需样本验证。
- 声纹模型使用 CAM++，单进程推理有锁，容量未压测；阈值需家庭样本校准。默认录入至少 2 秒、识别至少 0.8 秒，过短、低分、超时或服务异常均降级 Guest，迟到结果不改 Turn 身份。
- 豆包 ASR 当前每 utterance 建立独立 Provider WebSocket；短期对话只有一个当前 Session，不提供历史 Session 列表。
- 浏览器设备 ID 不是物理 MAC。清除 Cookie 后不能凭硬件自动找回家庭，应使用恢复码；服务端以凭据而非前端自报 ID 鉴权。
- 前端时延与音频诊断是当前页面会话数据，不持久化；历史恢复只有对话快照。已中断和失败在界面上区分展示。
- Dialogue 原文与 `memory_jobs` 均仍保留正文，尚无独立自动保留期限；应明确产品保留策略与存储容量，再实现自动清理，而不是让请求裁剪隐式删除原文。Memory 可关闭，Guest 仍能正常聊天。Vision、生产 CD 和声纹横向扩容未实现。
