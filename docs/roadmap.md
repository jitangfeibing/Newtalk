# Newtalk 后续路线图

只维护仍未完成的工作，实施历史查看 Git / PR，当前行为与限制查看 [architecture.md](architecture.md)。以下顺序是建议，不代表已经授权修改全部模块。

## 下一轮建议顺序

| 阶段 | 限定范围 | 完成标准 |
|---|---|---|
| 1：固定基线，再定位首声等待 | 保留当前可回退配置，固定 5 条输入、身份、记忆候选和上下文；分别记录冷启动与连续对话。 | 使用同一录音重复对照；串起词尾估计、VAD、ASR/声纹、检索、LLM 首字、TTS 首音和浏览器非静音输出。先确认最慢阶段，不同时调 VAD、模型和检索。 |
| 2：只优化证据指向的等待 | 优先检查首轮 ASR Final 尾延迟、普通闲聊的检索成本、首段文本到 TTS 首音的等待；每次只改一个环节。 | 对照固定基线，回复质量、身份隔离、记忆命中和打断不回退；收益不足可切回原配置。不承诺每轮低于 2 秒。 |
| 3：完善对话承接 | 先确定中断助手片段的可见性，再做可选目标状态、预算校准和必要摘要。 | “学英语 → 打断 → 继续”不丢已接受输入；闲聊不被强行锁定目标；未播放的助手内容不被认定为用户已听到。 |
| 4：可靠性与部署准备 | 按下表逐项处理取消等待、提交一致性和删除竞态；对外部署前再验收安全与多进程边界。 | 每项有 Event / Future 控制的回归测试；不把本机 CI 通过等同于云端容量或生产可用性验收。 |

当前 `preload` 和关闭思考模式已可通过配置使用及回退，但仓库默认仍是 `tool` 与供应商默认思考行为。真人测试显示首声等待改善趋势，问题和上下文尚未完全固定，不能作为严格 A/B 结论。下一轮从阶段 1 开始，不重复实现已经存在的开关或埋点。

## 功能规划：家庭日常陪伴（后续候选）

产品方向为家庭日常陪伴与记忆；本节维护提醒后续扩展、第三方音乐／播客、摄像头按需查看等候选。一次性提醒的已实现边界见 [架构说明](architecture.md#设备共享的一次性提醒)。当前页面控制的实际行为与限制见 [架构说明](architecture.md#当前页面控制)。以下优先级、交互和验收均为讨论稿，不代表授权启动其余功能、修改数据库或采购服务。

视觉采用前端摄像头开关与实时本地预览，需要看图的问题通过工具从当前画面截取一帧交给 VLM；不连续上传视频、不做后台看护。“音乐博客”暂按音乐／播客理解；音乐演示的实际能力见架构说明，喜马拉雅听书演示已接入，实际边界见架构说明。后续功能入口按语音控制、提醒、音乐／播客、看一眼分组；日常操作以对话调用为主。

### 建议交付顺序

| 阶段 | 用户场景与首版范围 | 验收与进入下一阶段的条件 |
|---|---|---|
| T1 后续：提醒扩展 | 在现有设备共享一次性提醒之上，按需要增加重复规则、稍后提醒、历史分页或独立闹钟。 | 明确时区、跨日和重复触发语义；不把播完等同于完成事项。 |
| T2 后续：媒体扩展 | 补音乐候选展示与选歌交互；按需要增加其他内容源及长音频功能。 | 延续真实播放回执与暂停规则，独立验收节目/单集选择及长音频播放。 |
| T3：按需视觉工具 | 手动开启摄像头并显示实时本地预览；“帮我看一眼桌上是什么”触发工具截取当前一帧，交给 VLM 识别并回答。 | 截图后保留预览，由用户开关控制摄像头；无连续上传；图片只关联当前请求，关摄像头、断开或离开页面时释放资源，失败后仍能正常聊天。 |

后续开发以当前提醒和音乐演示为基础；原有首声基线、取消等待与数据一致性工作仍保留。按触及范围解决相关阻塞，不要求先完成全部维护项，也不同时重写实时链路；其他播客内容源与视觉仍待单独实施。

### 提醒与闹钟的后续扩展

- 自然语言创建的执行结果核验：实测“正文完整保留”的较长创建请求出现仅口头确认、未调用工具的情况。后续约束模型完成条件并展示真实落库结果；当前以工具页实际记录为准，不能将口头答应视为创建成功。
- 依据实际使用再增加每日/工作日/每周重复、稍后提醒或持续响铃；重复规则必须覆盖时区与夏令时边界，不能直接反复修改一次性任务冒充调度模型。
- 评估提醒数量增长后的历史分页、待触发优先列表、自动保留期限和播报历史；当前只保留最近一次播报结果。
- 家庭内部私人提醒、代他人创建和成员删除关联需先定义权限，不能把当前设备共享表描述成成员隔离。
- 多进程投递需要共享连接注册/路由和恢复语义；当前单进程状态不能通过直接增加 worker 扩容。
- 页面关闭、设备休眠后的通知需单独评估 Web Push 或常在线终端；现有网页不能承诺准时唤醒和必达。

### 音乐后续与播客接入方案

- 音乐任务归属已落实到连接内媒体会话，实际边界见架构说明。继续由真人验收插话、切歌、追问状态和暂停/继续的体验；裸歌名承接及原有操作表达匹配本轮未调整。
- 模型混合文本与工具调用的兼容：真实供应商曾在普通文本后追加控制调用，当前适配器会明确拒绝混合输出。音乐普通聊天轮通过分离能力资料与操作工具避免该类误分流；通用混合流的缓存、TTS 与动作顺序仍需单独设计和取消测试，不能直接放宽现有拒绝逻辑。

- 音乐先保持功能演示范围，按实际需要补可点击候选列表、同名确认、下一首与队列。模型已有 search/序号能力，但完整候选交互仍需验收；搜索条目不能当作可播保证。第三方会员、地区与授权边界需在更换供应商或商用前重新验证。
- 喜马拉雅听书已接入；继续用真人语音验收“明确点播直接播、泛听帮助选择、有明显歧义才澄清”，以及自然简称/序号、换专辑、下一集/下一期。模型有界两步工具调用、候选隔离及取消已有自动化覆盖，不能替代真实识别和供应商可用性验收。
- 若接入 RSS 或其他节目源，再独立验证音频地址、单集排序与分页；不把喜马拉雅接口的行为假定为通用播客协议。
- 长节目需要的拖动、播放进度、断点续播、跨设备恢复应另定持久化与权限范围；当前刷新/断线会清空播放器，不宣称已经支持恢复。新增数据表或迁移需另行明确授权。
- 收藏、睡眠定时和偏好记忆按需要追加；单次播放不自动推断永久偏好。视觉与会员登录仍待另行实施。

#### 媒体后续验收与扩展边界

- 媒体任务归属、提交点、取消规则及反馈统一见 [架构说明](architecture.md#音乐演示与媒体播放)；旧本地方案图仅作历史对照，不作为现行实现。
- 继续在真实供应商和浏览器验收“点播后插话询问进度”“解析时暂停/继续”“连续换歌/停止”“提醒与聊天结束后新曲开始”；自动化取消测试不能替代 ASR、模型判断及真实音源可用性验收。仅有空地址不能判断版权或会员原因。
- 新增内容源继续经 MediaCommands 提交独立 MediaIntent；针对各源分别定义稳定身份、分页、排序及有效资源，不把当前接口的临时序号当作永久编号。
- 完整工具消息的持久化、固定失败语音提示、跨页面统一播放、多实例资源路由和跨断线恢复均未实现，按实际需要单独设计；不增加全局事件总线、持久化媒体任务平台或播放队列。

### 摄像头按需查看

- 前端提供摄像头开关、实时本地预览及截图／识别状态。手动开启并获得浏览器授权后保留预览，不自动上传预览视频；用户关闭摄像头、主动断开聊天或离开页面时停止轨道并释放资源。截图完成或单次识别取消／失败时不擅自改变用户的摄像头开关状态。
- 模型根据当前问题决定是否调用视觉工具；工具取得当前帧及当前问题，交给 VLM 返回观察结果，再由对话链路完成文字与语音回复。工具名暂用 `camera_snapshot` 表达意图，最终协议另定；截图与 VLM 分析作为一次业务工具操作，不要求模型分两次调用。普通聊天不取图，“再看一下”重新截取新帧，不复用上次图片冒充当前画面。
- 摄像头关闭、尚未授权或没有就绪视频帧时，提示用户开启／等待，不自动打开设备，也不假称已经看到。开启前说明预览为本地画面，需要看图时才将截图发往所配置的视觉服务；用户请求一次看图即可触发该次截图，不额外逐帧确认。
- 首版处理物品、场景与文字问答，允许明确表示看不清并请求重拍；不从画面推断成员身份或覆盖声纹／文本所选成员，不自动触发提醒等其他有副作用的动作。
- 取图请求必须关联当前设备、连接、Turn 和请求标识，并设截止时间；记录取帧时间，结果对应这一帧，不宣称描述回复时刻的实时变化。等待浏览器响应及视觉服务运行在独立可取消任务中，不向 WebSocket 接收循环新增内联外部等待。被打断、关闭摄像头、断线或超时后的迟到图片／结果不能用于下一轮。
- 增加受限的图片传输与接收“图片＋问题”的 VLM 适配能力，限制格式、尺寸、字节数及保存时间；主对话模型可继续接收工具返回的文字观察结果，不必先整体改造成多模态模型，当前纯文本消息接口也不能只靠增加工具名称获得看图能力。首版原图仅作临时处理，不进入 Dialogue、长期记忆或正文调试日志；回答中的视觉事实标记为本次观察，不自动写入成员画像或长期记忆。外部视觉服务的数据保留需按所选供应商实际配置核验。
- 验收覆盖开关与预览、仅在工具调用时上传当前帧、连续提问取得新帧、识别后预览保持开启、关闭／断开／离页后资源释放，以及首次授权、拒绝／忽略授权、无设备、摄像头占用、超大／非法图片、重复回传、跨连接回传、取消及超时后的迟到结果；失败后可继续纯语音或文字对话。

### 三类工具共用的最小边界

- 工具是否可用由服务配置、客户端能力和服务端权限决定；模型只提出意图与参数，不能指定任意家庭、成员或绕过权限。首版每轮最多一个业务动作，复合请求拆步骤，暂不做无限工具循环或新增 Intent / MemoryRouter；记忆检索开关不得关闭其他业务工具。
- 读操作、持久化写操作和客户端操作分别定义完成条件。提醒创建只有确认落库才称成功，媒体只有客户端开始播放才称播放中，视觉只有取得当前图片并完成识别才回答观察结果；超时或结果未知不得当作成功，也不盲目重试写操作。
- 有副作用的动作使用持久化执行标识去重，记录提交结果；聊天打断只取消未提交的动作，已保存的提醒不会随 TTS 取消而撤销。回包丢失时可查实际结果，避免重试创建两份任务。
- 最小记录包含工具、请求／Turn、设备／成员范围、耗时及执行状态；正文、图片和密钥不进入普通日志。外部工具内容作为资料处理，不能自行授权拍照、播放或创建任务。
- 实施时按实际行为更新架构与协议；新增表或迁移须作为独立明确范围审查，本讨论稿不直接决定数据库约束。涉及实时运行逻辑时补相关取消、超时和并发测试，并运行前端测试与完整后端回归。

浏览器约束参考：[自动播放限制](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)、[Push API 与 Service Worker](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)、[摄像头权限与安全上下文](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。浏览器策略、通知与所选 Provider 的可用性须在目标设备上实测。

## 优先：实时链路与数据一致性

| 工作 | 验收标准 |
|---|---|
| 停止采集与取消的等待预算 | ASR / Provider 不结束时，接收循环仍能处理控制消息和断开；使用 Event / Future 测试超时、取消和资源回收。 |
| Turn 提交一致性 | 在 Dialogue 追加、记忆入队期间注入打断/数据库错误，内存、持久化、任务和客户端状态有明确一致结果。先确定提交点，再小范围调整。 |
| 成员删除的剩余竞态 | 覆盖“身份校验后才删除”“Profile 加载中删除”；不得写回已删成员 Dialogue 或重新建立 Profile。 |
| 身份查询故障分类 | 数据库故障不误报为 ASR 识别失败；文本和语音路径有明确错误或降级规则，并证明连接可恢复。 |

原始问题证据见 [审查快照](audits/2026-10-22-code-audit.md)；已修复事项的交付以 Git / PR 为准，不要把整份历史报告直接当待办。

## 随后：上下文与音频体验

- **中断助手片段语义**：已接受的最终用户输入已独立保留；下一步明确助手的生成、发送、实际播放片段如何区分及进入上下文，不将未播放文本当作用户听过的回复。
- **预算校准与长程目标承接**：完整输入预算、原文/候选分离和看板已实现；下一步用实际 Tokenizer/usage 校准估算，实测首字延迟、费用和跨预算的长任务。不能把扩大窗口等同于目标状态已经实现。
- **必要的会话摘要**：依据预算与对话质量决定触发频率，从保留的原文生成带来源范围的摘要；保留近期原文、用户更正及不确定性，避免把助手建议当成用户目标。后台摘要失败不能删除原文，清空后旧摘要不能回灌。闲聊允许没有目标，不新增每轮 Intent LLM。
- **前置检索试验验收**：已支持可回退的 `preload` / `tool` 模式；用单轮日志比较检索等待、模型请求次数、首字/首段语音以及候选相关性，特别验证普通闲聊是否反而变慢。确认后决定默认模式，投机预取、查询缓存暂不实现。
- **5 轮语音时延验收**：VAD 末尾、ASR/声纹汇合与浏览器非静音输出计时及最近 5 轮导出已接入，已有真人 5 轮样本。严格 A/B 仍需同录音、人工词尾和固定记忆/上下文；尚未进行声学回环测量，不能把估算标为物理听到时间。
- **LLM 首轮等待复验**：细分连接/响应/思考/首字计时和固定请求诊断脚本已接入，SDK 本地资源初始化已前移启动。本机已通过显式思考开关切到 `disabled`，并完成真人回复与首声测试；仍需同条件重复对照及复杂任务质量验收。自动切换深度模式尚未实现，不据少量请求承诺固定延迟收益。
- **连续 utterance 顺序**：用可控时序复现旧 Final 晚到，确定丢弃、合并或保留规则，防止用户继续讲话时播放过期回答。
- **声纹准确率与容量**：用不同内容、长度、距离和家庭成员样本记录分数、误识别和降级原因；再测排队与推理耗时，决定是否多进程或多实例。
- **音频稳定性**：已有诊断和时延面板，下一步收集耳机/外放、安静/噪声样本，先定位回声、VAD 或模型问题，再决定工程级 AEC 范围。

## 按实际改动推进的维护项

- 为 SQL 与内存 Store 增加相同场景的契约测试，减少测试替身语义漂移。
- 为已完成/失败的 Memory Job 明确保留期限；评估优雅关闭期间的投递确认窗口。
- 明确 Dialogue 原文的自动保留期限、容量限制与历史分页；原文存储不再跟随模型请求窗口自动淘汰。
- 共享数据库连接资源、简化配置组装、分离应用导入副作用，均先测影响范围，不一次重写。
- 前端按协议客户端、录音/播放和视图逐步拆分，保留现有接口与四视图行为；不以换框架为目标。
- 数据库 lane 简化涉及迁移与窗口语义，不能当作无用字段直接删除。

## 暂不启动
